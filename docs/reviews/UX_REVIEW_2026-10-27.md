Follow-up correction after owner feedback: the marketing page intentionally
minimizes competing actions (see `docs/LANDING_CONVERSION.md`). The general
heuristic score below does not measure conversion performance. Removed this
review's added landing-page setup paragraph, setup section and guide/account
links; the complete setup instructions remain in the account guide and apps.
Preserved the primary trial CTA, pricing, product demo, factual compatibility
copy and keyboard/touch improvements. Future marketing review should prioritize
page CRO and actual funnel results, using Impeccable for visual/accessibility
support. No conversion lift is inferred from this correction.

Correction verification: 166 website checks passed; checked the compact page at
1440px and 390px with exactly one visible primary trial button, the original
trial destination, no horizontal overflow and no browser errors. Updated
screenshots/results are in `build/ux-marketing-focus-20261027/`.

Saiph has a recognizable cyan/violet wave identity and a useful device demonstration. The biggest problem was the journey between surfaces: a clear no-card trial led into documentation for an older, manual-code connection flow. The apps already supported a much simpler nearby/QR path. Correct instructions and truthful completion states matter more here than a visual redesign.

The marketing animation, clear trial terms and explicit device approval are strengths. Remaining opportunities are consistent branding across marketing/account/apps, larger desktop helper text, and shorter mobile instructions with optional detail disclosed at the point of need.

## Priority feedback and changes made

1. **P1 — Make the website and apps describe one setup path.** Rewrote `account-web/app/setup/page.tsx`: obtain trial/subscription/invitation access, install both apps, start in desktop Phone, use the same account, find the computer or scan its QR, compare and explicitly approve, then send a harmless test file. Manual codes and joining another computer are secondary disclosures. Replaced obsolete scrcpy/OBS webcam directions with the current integrated camera route and its Windows limitation. Suggested follow-up: `/impeccable onboard` for a shorter mobile presentation.
2. **P1 — Make free-trial access discoverable from Account.** An available trial/subscription block now appears before invitation redemption. Account entitlement, billing and authentication logic are unchanged. Suggested follow-up: `/impeccable layout` for clearer alternative access methods after the lead action.
3. **P1 — Never celebrate the wrong connection.** The optional desktop guide excludes other computers from the phone count and reports saved preferences without claiming an online phone. The pairing wizard matches completion by approved device ID, so an older phone with the same name cannot falsely finish a new phone's setup. Regression tests cover both failures. Suggested follow-up: `/impeccable harden` on offline/recovery states.
4. **P2 — Set accurate expectations before sign-in.** Marketing visibly names Windows/Linux and says “no server to run.” Following owner feedback, installation and approval instructions stay in the account guide and apps, keeping the landing page focused on the trial/purchase action. Android makes Continue with Google primary, puts plans second and explains the same-account requirement. Suggested follow-up: conversion-focused review of the landing page and `/impeccable clarify` across account entry points.
5. **P2 — Give waiting and success useful next actions.** Added a first-file test after desktop connection, recovery advice after approval, and an operable desktop-download action for an unconfigured source build. Android's nearby waiting screen now displays the six-digit comparison code it asks the person to check; QR enrollment still displays the full fingerprint. Existing owner verification and approval requirements remain in place.
6. **P2 — Fix keyboard behavior in the demo and optional guide.** Marketing feature tabs now support arrows/Home/End, one tab stop, panel relationships and 44px minimum height. Automatic scene selection pauses while focus is in the demo. Desktop guide headings receive focus on entry/step change; connection choices expose their selected state.

## Personas, load and emotional journey

- **Jordan, first-time user:** The former invitation-first account layout and manual root-code guide made an ordinary trial look restricted or broken. Lead with the next action and use the app's exact labels.
- **Sam, keyboard/assistive technology:** Marketing tabs had click-only switching; the guide lost focus at step changes. These are fixed. Tiny desktop helper text still needs a dedicated typography pass.
- **Casey, interrupted mobile user:** The trial page works well at 390px, but a long guide still requires substantial reading and app switching. A future compact step view should keep the current step visible and optional methods collapsed.

The original emotional valley came after a reassuring no-card trial: people encountered unexpected technical setup. The revised account/app route explains the essential work when people begin setup and ends with an observable file transfer instead of an unconditional “all set.” Seven marketing demos are browseable options; account access, device approval and optional sharing should remain separate decisions.

## Detector findings and limits

Final changed-source pass: 8 findings, all attributed to `website/index.html` at rendered line 0: three low-contrast advisories inside the illustrative device animation, plus cramped-padding, ai-color-palette, pulsing-dot, dark-glow and radial-halo. Palette/glow findings overlap existing branding; the borderless device illustration is not a form with cramped controls. The three contrast advisories and small demo/footer text are useful polish leads. No claim of a globally clean accessibility audit is made.

Browser overlays: homepage 12 findings; downloads 0; features 4. These are different scopes, not additive counts. Account guide's strict CSP blocked the detector's WebAssembly; it was not weakened. Desktop CDP scan returned 2 incumbent brand findings (palette and gradient wordmark); pixel contrast timed out. The detector changed the offscreen emulated viewport, so final routine desktop checks used a clean new session. Overlays were temporary QA artifacts and are not left in a user's browser.
